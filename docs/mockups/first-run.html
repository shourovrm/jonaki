First run: four setup cards, each with Skip

A fresh install opens on an empty thread list. Nothing on it says that Jonaki needs an API key and a model before it can answer, so the first message fails. The proposal below asks four questions, one card at a time, on the first launch only. Every card can be skipped, and "Skip all" leaves at any point. Whatever was skipped stays on the thread list as a short to-do until it is done or hidden.

Why four cards and not more

A model is the only thing Jonaki cannot work without. Web search, approvals and notifications are the three choices that change what the first long task feels like. Pictures, video, subagents, memory and MCP servers all work or stay off without a decision, so they stay in Settings.

What the cards reuse

Each card writes the same settings that Settings already writes: the service list, the key store, the model picker's list, the search order, the approval mode and Android's notification permission. No new kind of data is stored, apart from one flag that says the cards were shown.

Template patterns kept out

There is no welcome screen, no feature tour, no illustration and no "You're all set" page. Choices are plain rows with a radio button, not a grid of icon tiles. The count "1 of 4" is the only progress mark, and the card edges underneath show the same thing physically. The only glow on these screens is the firefly dot of the running task in the notification preview, which is where the app uses it.

What I would like you to decide

The services at the top of card 1. I put OpenRouter, Gemini, DeepSeek, OpenAI and Ollama on this network first. The on-phone model could be a sixth row, but it needs a large download, so I left it under "7 more". Card 3 offers two of the three approval modes.
