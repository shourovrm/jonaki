Subagents: the list while running, the subagent page, and checking the work

Every screen follows direction A (Lantern) with the Leaf colours. One example runs through the page: a user asks, partly in Bangla, for a laptop under ৳80,000 for her sister. The main agent starts three researchers (Star Tech, Ryans, Daraz) and one writer, which reads the department's spec sheet and drafts a Bangla page for their mother. The firefly yellow-green appears only on work that is running at that moment.

1. The list while running, option A: rows inside the run (recommended)

The delegate step in the run track turns into a group with one row per subagent. Each row shows the task on one line ending in "…" (D-029). Under the task are the type and what the subagent is doing now. Steps used of 10 and the cost sit on the right. The station of the group shows "N of 4 done", which is the only overall progress.

How it reads

  • No card per subagent. The rows share the run's border and hairlines, so four subagents take about the height of today's two cards.
  • Only a running subagent gets the glow dot. Done shows a check, a request shows a hand, asking the main agent shows a speech bubble, and a stop for a limit or failure shows a warning sign. All of them are in ink colour.
  • The second line turns full ink when the subagent needs a look ("Waiting for you", "Over budget"). That way, the rows that need a decision stand out without a second colour.
  • Failed, Timed out, Out of steps and Stopped use the same warning row as Over budget, with their own words.
I recommend A. It keeps every fact the user needs in one place: what each subagent was asked, what it is doing now, and its steps and cost against the 10 and $0.10 limits. It also adds no new surface to the chat. Tapping a row opens that subagent's page.

1. The list while running, option B: a dock above the composer

The run track keeps a single "4 subagents" station. A row of chips sits above the status strip while any subagent runs. Each chip has a short name, a status icon and its steps. The dock stays visible while the user scrolls the chat, and it goes away when the last subagent ends.

How it reads

  • The dock is always in view, even when the run block has scrolled away under a long answer.
  • Chips order themselves: running first, then the ones that need a look, then the finished ones.
  • At 360 px only three chips fit; the fourth scrolls. The task does not fit at all, so each chip needs a short name ("Ryans", "Guide"). delegate has no such argument today, so the model would have to send a label or the app would have to guess one.
  • The dock also takes 44 px from the chat for the whole run, and the cost per subagent is hidden until a chip is opened.
B is weaker. It gives up the task text and the cost to stay in view. Staying in view matters less here because a request to the user already brings its own approval card into the chat.

2. Opening a subagent: a full-screen page

A tap on a row opens the subagent's own page. The page shows the whole task, steps and cost against the limits, the step track in the same station style as the main run, the answer, the files it wrote, and its skipped parts. The arrows in the top bar move to the next or previous subagent of the same call. While the subagent runs, a bar at the bottom holds a Stop for that subagent alone.

Why a full screen

  • An answer can be 16 KB (D-060). That is too long for a sheet, and a page scrolls like any other screen.
  • Open on a file goes to the file viewer, and Back returns to this page and then to the chat at the same spot. With a sheet, the viewer would have to cover a sheet.
  • The arrows step through the four subagents without going back to the chat.

Order on the page

  • While running, the steps come first. When done, the steps fold to one line, and skipped parts, files and the answer move up, because those are what the user came to check.
  • The meters use ink, not the accent: a budget is not live work.

3. Checking the work after the run

When the run ends, the run block folds to one line as today. Under the answer, one row names the subagents and flags any that stopped early. The row opens a sheet with the same rows as option A. The sheet also links to the notes board and to every file the group wrote.

From the answer to the work

  • The "Work from 4 subagents" row lists only what went wrong and the note count. When everything is fine it reads "All done, 6 notes".
  • The sheet reuses the rows from option A in their final state. A tap opens the same subagent page as in section 2.
  • The notes board is notes.md from the delegate folder, shown in the file viewer with the author and time of each note. Here the user can see which numbers the researchers checked against each other.
  • A file a subagent wrote also gets its own Open row in the chat, labelled with the subagent's name (D-066).
